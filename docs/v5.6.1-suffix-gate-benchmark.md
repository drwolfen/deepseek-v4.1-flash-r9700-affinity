- **Prose / DSpark Parity Recovered Without Losing `code_edit`**:

  - On `code_edit.txt` (`NGEN=256`), `v5.6.1` delivers **`43.51 tok/s` warm `tg2`** (`99.6%` acceptance, **`8.00 tok/blk`**), outperforming pure DSpark (`39.62 tok/s`, **`+9.8%`**), tightened Option 1 thresholds (`39.79 tok/s`), and `v5.6.0` (`41.50 tok/s`, **`+4.8%`**).
- **Long-Context & Short-Context Gains Maintained**:
  - `p4k.txt` (`NGEN=16`): `tg2 = 18.23 tok/s` (`+5.9%` vs `v5.6.0` `17.21`, `+11.3%` vs `v5.5.0` `16.38`).
  - `l4k.txt` (`4,031` tok): `pp1 = 647.8`, `tg1 = 27.71`, `tg2 = 46.48 tok/s` (`+1.8%` vs `v5.6.0` `45.65`, `102.4 ms/blk`).

  - `l64k.txt` (`63,863` tok): `pp1 = 1,452.5`, `tg1 = 45.85`, `tg2 = 46.81 tok/s` (`+5.3%` vs `v5.6.0` `44.47`, beating `v5.4.0` `46.73`; **`99.8 ms/blk`**).

## 2. Root Cause Investigation (`v5.6.0` Prose `tg` vs `v5.4.0`)

Investigating why `v5.6.0` reported lower `tg2` on prose (`45.65 / 43.81 / 44.47` and `19.70` 4-prompt DSpark) than `v5.4.0` FAST (`48.24 / 45.81 / 46.73` and `22.70`) revealed three separate factors:

1. **Per-block speed was NOT slower**: `--default-effort` did not affect any benchmark (all evaluations used `--default-effort 60`), and `v5.6.0` already executed individual verify blocks **4.4%–20.0% faster** (`ms/blk`) than `v5.4.0` thanks to Wave 8 (`R1–R6`) and Wave 9 (`F1–F8`).
2. **Un-gated `SuffixDraftIndex` (`R6`) single-occurrence 4-token prose collisions**:
   - In `src/engine/suffix_draft.h`, a trailing 4-token pattern appearing only once earlier in the prompt or prose continuation scored `tok_cnt / tot_cnt = 1 / 1 = 1.0`, yielding `expect = 12.0 >= 2.0`.
   - Under static thresholds (`AFF_DRAFT_SUFFIX_MIN_MATCH=4`), CPU suffix drafting preempted GPU DSpark (`3.5–4.5` accepted tok/blk), verifying 12-token prose guesses that frequently rejected at position 0–1 (inflating verify block width `q = 13`, triggering PCIe expert misses, and reducing `tok/blk`).
   - Additionally, in `v5.6.0`, `code_edit` ran prior to `step_c` and evicted prose-specialized resident experts before the 4-prompt measurement.
3. **Observed Engram Page-Cache Confounder (`sar -B` & `mincore`)**:
   - Across `arm1` (`2,332` avg `majflt/s`, `1,041–2,796 majflt/s` in `step_c`) and `arm2` (`3,050` avg `majflt/s`, `1,041–4,160 majflt/s` in `step_c`), container restarts preceded by kernel page reclaim (`pgsteal/s = 61,053–91,460`) left the two `94.56 GiB` Engram weight shards (`189.1 GiB` total) at ~`1.7%` (`3.20 GiB`) host page-cache residency (`madvise(MADV_WILLNEED)` under `AFF_ENGRAM_WARM=1` is advisory on Linux 7.0 and returns asynchronously before faulting all pages).
   - Host demand-paging stalls starved GPU execution during `step_c` (`busy 86–87%`, `sclk ~3,000 MHz` vs warm `99–100%`, `sclk ~3,530 MHz`), costing **+15–22 ms/blk** even on identical token streams (`json_schema` emitted identical `sha256_12 = 4c6cdf0c65b3` on both `arm2` and `arm3`, running `199.45 ms/blk` vs `177.74 ms/blk`).
   - When launched into warm Engram page cache (`arm3`: `124 majflt/s`; `arm4`: `85 majflt/s`), block times dropped directly into the `138–183 ms/blk` regime. Full synchronous/pre-faulted Engram table warming is left out of `v5.6.1` scope and tracked as a future optimization candidate.

## 3. `SuffixGate` Architecture (`v5.6.1`)

`struct SuffixGate` (`src/engine/suffix_draft.h`) sits between `SuffixDraftIndex::propose` and GPU `dspark_draft` in `tools/affinity.cpp`:

- **Env Controls**:
  - `AFF_DRAFT_SUFFIX_DYNAMIC` (default `1`; `"0"` restores static `R6` gating).
  - `AFF_DRAFT_SUFFIX_GAIN` (default `1.05`, clamped `>= 0.5`; minimum utility multiplier over DSpark).
  - Existing `AFF_DRAFT_SUFFIX_MIN_MATCH=4`, `MIN_SCORE=0.35`, `MAX=12`, `MIN_EXPECT=2.0` defaults are kept intact so repetitive multi-line code edits still capture full 8–12 token blocks.
- **Anchor-Length Guard Under Active DSpark (`cfcbb18`)**:
  - Cold prose entry requires `prop.match_len >= min_match + 2` (`>= 6` exact anchor tokens), eliminating 4-token and cold 5-token chance prose collisions with zero wasted verification probes.
  - Once inside a proven high-acceptance suffix streak (`steps > 0 && miss_streak == 0 && acc_ema >= 0.80f`), the required anchor relaxes to `min_match + 1` (`>= 5`).
- **Live Utility & Acceptance Backoff**:
  - Tracks empirical acceptance rate (`acc_ema = 0.55 * acc_ema + 0.45 * (k / nd)`, initialized `0.90f`) and compares effective suffix utility `(1 + prop.expect * acc_ema) / cost_ema[prop_nd + 1]` against live DSpark utility `(1 + dspark_exp_acc) / cost_ema[B + 1] * sfx_gain`.
  - Requires `k >= 2` and `k * 2 >= nd`; otherwise arms exponential miss cooldown (`2, 4, 8, 16` checks), breakable only by long anchors (`>= min_match + 2` and `n >= min_match + 2`) while `acc_ema >= 0.65f`.

## 4. 4-Arm Controlled Evaluation (`--default-effort 60`, NUMA Node 0 `N0=100%`)

All four arms ran cold-start (`GPU[1] <= 52 C`, `req00 <= 0.47 s`, `0` `hipError`, `N0 = 47,804,160 / 47,804,160 = 100.0%`, `3,644` resident experts, `pcache` fp `0x733de762fee543e6`) on `ROCm 10.1.0-full` with identical step order (`p4k -> l4k/l16k -> l64k -> step_c -> code_edit`):

- **Arm 1 (`arm1_opt2_dynamic`, `rc1`)**: Initial `SuffixGate` (`AFF_DRAFT_SUFFIX_DYNAMIC=1`), no anchor guard.
- **Arm 2 (`arm2_opt2_plus_opt1`, `rc1 + Option 1`)**: Initial `SuffixGate` + `MIN_MATCH=6`, `MIN_SCORE=0.65`, `MIN_EXPECT=4.5`, `MAX=8`.
- **Arm 3 (`arm3_pure_dspark`, `AFF_DRAFT_SUFFIX=0`)**: CPU suffix drafting disabled completely.
- **Arm 4 (`arm4_opt2_v2`, `v5.6.1` final `cfcbb18`)**: Refined `SuffixGate` with `>= min_match + 2` cold / `>= min_match + 1` streak anchor guard and `AFF_DRAFT_SUFFIX_*` defaults.

## 6. Context Window Sizing for `--default-effort 75`

No increase above `--kv-size 327680 --kv-commit 262144` (and `310,000` client context / `0.50` compression threshold) is needed or recommended when using `--default-effort 75`:

1. Multi-turn conversations strip prior `<think>...</think>` reasoning blocks between turns, so `--default-effort 75` only increases the current turn's reasoning scratchpad, not cumulative multi-turn context growth.
2. Within each turn, `AFF_NOBUDGET_MAX_TOKENS=24576` + `AFF_THINK_REPLY_RESERVE=4096` caps `<think>` at `20,480` tokens before automatic closure.
3. Raising `--kv-commit` to `512K` would consume ~`340 MiB/card` of permanent monotonic VRAM (`VirtualSpan::commit_to`), evicting ~`55` GPU-resident MoE experts and lowering decode throughput.
