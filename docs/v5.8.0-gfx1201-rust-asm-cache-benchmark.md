## 2. Dual `gfx1201` Hardware Topology & Optimization Rationale

1. **Compute & Wavefront (`gfx1201`, RDNA 4, Wave32)**:
   - Dual-issue Wave32 SIMD units, WMMA matrix instructions (`16×16` tiles), 64 KiB LDS/CU (`128 KiB/WGP`), and 256-entry VGPR files per SIMD where crossing `224 -> 248` VGPRs drops wave occupancy sharply (`expert_gemm_wmma_kernel <*,*,5,1>` stays at `[57, 123, 194, 223]` VGPRs / `flash_kernel<2>` stays at `230` VGPRs).
   - Pure-LDS barrier `aff::lds_barrier()` (`asm volatile("s_waitcnt lgkmcnt(0)\n\ts_barrier")` in `src/gpu/hip_common.h`) avoids full vector/scalar memory counters (`vmcnt(0)`) on LDS-only exchanges, while Wave32 `dpp_xor_lane<Lane>()` + `wave_reduce_{add,max}_dpp()` replace shared-memory wave reductions inside `sampler_gpu.hip`, `tp_allreduce.hip`, `indexer_gpu.hip`, and `moe_plan.hip`.
2. **Cache Hierarchy (8 MiB L2 + 64 MiB Infinity Cache MALL)**:
   - Streaming single-use routed expert weights (`6.08 MiB` shards read once per token) benefit from `ld_nt` inside `expert_gemm_wmma_kernel`. Conversely, dense attention/FFN projections, KV-Q/O weights, and DSpark Markov matrices are reused across speculative draft/verify steps and fit within L2/MALL. Using `TH_LOAD_NT` across those 20 dense/GEMV paths (`AFF_DENSE_NT_LOAD=1`) evicted/bypassed L2+MALL and degraded `l4k tg2` by `-23%` (`53.97 -> 41.50 tok/s`).
3. **Host CPU (`2× Xeon Platinum 8160`, 754 GiB DDR4, NUMA 0 & 1)**:
   - Pinning HTTP/tokenizer/worker threads to `--cpuset-cpus=0-23,48-71` (`AFF_PIN_NUMA0=1`) keeps host work local to both R9700 GPUs on NUMA Node 0, while 256-bit AVX2 copies in `EngramTables::gather_mxfp8()` avoid Skylake-SP AVX-512 License L2 downclocking.
