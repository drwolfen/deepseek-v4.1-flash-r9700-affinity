## 1. Executive Summary

`v5.10.0` (`e0ac5c3`, Wave 13) verifies and lands the ephemeral `/btw` KV cache storage/transfer findings that missed `v5.9.0`, audits every Affinity storage tier against next-step compute consumption, evaluates `StillDeadcode/radiance` `v2.2` (`b6b8751c`) — including its `IQ8R` / `IQR-V4`-only weight-format pivot — and benchmarks DSpark speculative drafting placement and pruning strategies on dual `gfx1201`:

- **Verified `/btw` Audit + Optimal Data Format Assessment across All 5 Storage Tiers**:
  - Confirmed `/btw` (`992b46f2`) had not been applied to `v5.9.0`; Waves 1–2 landed lazy KV chunk commits (`AFF_LAZY_BKV=1`), block-aligned KV backing (`AFF_KV_ALIGN_COMMIT=1`), conditional skipped `n_comp` allocation when dense KV is unaliased (`AFF_KV_SKIP_DEAD_NCOMP=1`), fused indexer RoPE+QAT+quantize (`AFF_FUSE_IDX_Q=1`), and coalesced KV norm+commit (`AFF_KV_COMMIT_COALESCED=1`).
  - Audited host SSD/RAM (`2.875-bpw` `AFF_Q2P875_Q4` immutable THP N0 pool), prefix cache (`RIDX` v2 delta checkpoints on NVMe), KV cache (FP8 E4M3 `VirtualSpan`), Engram/Indexer intermediates, and DSpark draft buffers. Keeping `.aff` `2.875-bpw` routed experts + native FP8 E4M3 linear/KV paths preserves `gfx1201` hardware WMMA (`v_wmma_f32_16x16x16_fp8_fp8`) and maximizes PCIe-avoiding VRAM residency.
- **Radiance `v2.2` (`b6b8751c`) Cherry-Picks & Negative-EV `IQ8R` / `IQR-V4` Rejection**:
  - Adopted `v2.2`-inspired wins compatible with `gfx1201` FP8/FP4 execution: `idx_block_max_b8_kernel` + 11-bit radix top-k (`AFF_IDX_TOPK_V2=1`), multi-token indexer candidate scoring (`AFF_IDX_CAND_MULTITOK=1`), split Flash v2 (`AFF_FLASH_SPLIT_V2=1`), double-buffered prefix-cache pipeline (`AFF_PCACHE_PIPELINE=1`), and adaptive `q=1` draft gating (`AFF_DRAFT_ADAPTIVE_Q1=1`) / Markov exact pruning (`AFF_MARKOV_EXACT_PRUNE=1`).
  - Rejected converting `.aff` weights to Radiance `v2.2` `IQR-V4` (~4 bpw trellis) or `IQ8R` (`int8 + fwht128`): 4 bpw routed experts would cut GPU residency by ~28% over PCIe Gen3 ×16, and `IQ8R` replaces native `gfx1201` FP8 E4M3 WMMA with software FWHT + integer unpack overhead.
- **`+12` Live GPU-Resident MoE Experts (`3,934 -> 3,946`) & `fast_w123_pipe` Speedup**:
  - Reclaiming prefill arena (`654 -> 592 MiB/card`, `-62 MiB/card`) and compressor+indexer (`112 -> 102 MiB/card`, `-10 MiB/card`) raised GPU-resident routed experts from `3,934` to **`3,946`** (`3,888` shared = `25.3%` symmetric base + `58` Card-1 bonus shards / `352.6 MiB`).
  - In paired FAST-regime testing (`fast_w123_pipe` vs `fast_v590_ctrl`), the locked `v5.10.0` defaults raised **`l16k tg2` from `54.80` to `57.91 tok/s` (`+5.68%`)**, **`l4k tg2` from `49.36` to `50.42 tok/s` (`+2.15%`)**, cut **DSpark block latency from `141.97` to `133.72 ms/blk` (`-8.25 ms/blk`, `-5.81%`)**, and raised 4-prompt **DSpark acceptance from `71.61%` to `73.98%` (`+2.37 pp`)**.
- **DSpark All-VRAM Placement (`384/384`) Proven Optimal over Host-Pooled Streaming**:
  - Sweeping `--dspark-vram-experts` across `{384 (default), 256, 128, ram}` proved offloading DSpark experts to host RAM severely degrades decode (`41.37–44.33` vs `50.42 tok/s` `l4k tg2`, `41.96–45.24` vs `57.91 tok/s` `l16k tg2`) and slows prefill (`-8%..-12%`) due to spawning extra CU-masked `8/32`-WGP hybrid streams under `GPU_MAX_HW_QUEUES=1`. `--dspark-vram-experts N` remains available as opt-in while keeping `384/384` VRAM default.
- **Empirical Ablation of `AFF_POOL_MLOCK` and `AFF_FUSE_WOA_Q8` (Locked Opt-In `=0`)**:
  - Paired FAST wave bisection (`bisect_table.json`) showed Wave 1 (`127.58 ms/blk`), Wave 2 (`129.56 ms/blk`, `54.82` `l16k tg2`), and Wave 3 (`132.35 ms/blk`) drove the speedup, whereas Wave 4's `AFF_FUSE_WOA_Q8` (`w4_only`, `141.52 ms/blk`) and `AFF_POOL_MLOCK` (`mlock_only`, `140.93 ms/blk`) were flat/negative and triggered `RC2` latency/acceptance drops (`67.47%` vs `73.98%`). Both were flipped opt-in OFF (`=0`) in `e0ac5c3`, leaving `AFF_PCACHE_PIPELINE=1` and Waves 1–3 default ON (`=1`).

## 2. Architecture & Trade-Off Evaluations

### 2.1 Storage Format Audit (`.aff` vs `IQR-V4` / `IQ8R`)

| Tier | Current Affinity Format | Next-Step Compute Consumer | Evaluation Verdict |
|---|---|---|---|
| **Routed MoE Experts (15,360 slots)** | `2.875-bpw` `AFF_Q2P875_Q4` (182.4 GiB THP N0 + 3,946 GPU VRAM) | `expert_gemm_wmma_kernel` on `gfx1201` | **Keep Optimal.** Moving to ~4 bpw `IQR-V4` would shrink GPU residency by ~28% and inflate PCIe Gen3 ×16 misses. |
| **Dense Linears & LM Head** | Native FP8 E4M3 (group-128) | `v_wmma_f32_16x16x16_fp8_fp8` | **Keep Optimal.** `IQ8R` (`int8 + fwht128`) trades native `gfx1201` FP8 WMMA for software transform/unpack overhead. |
| **KV Cache (`327,680` span / `262,144` commit)** | FP8 E4M3 `VirtualSpan` + coalesced norm commit | `attn_flash` / `idx_block_max_b8` | **Optimized (`v5.10.0`).** Added lazy KV allocation, aligned commits, dead `n_comp` skip, and coalesced writes. |
| **Indexer (`Q` / `K`)** | Fused RoPE + QAT + FP8 E4M3 quant (`VirtualSpan` lazy) | `idx_cand` + 11-bit radix top-k | **Optimized (`v5.10.0`).** Eliminates unfused intermediate memory traffic and widens candidate scoring. |
| **Prefix Cache (NVMe)** | `RIDX` v2 (`magic=0x52494458`, `block_tokens=512`) delta checkpoints | Double-buffered `gather[0..1]` restore (`AFF_PCACHE_PIPELINE=1`) | **Optimized (`v5.10.0`).** Exact `payload_bytes` delta reads + overlapped H2D/restore. |

### 2.2 Radiance `v2.2` (`b6b8751c`) Feature & Weight-Format Assessment

- **Analyzed `StillDeadcode/radiance` `v2.2` commits**: `17b556d9` (DSpark), `ff19013a` (`dspark_rnn_markov_greedy`), `3ee49eed` / `4865bd6b` (queue reserve), `e22a4668` / `fb39c877` (wide scalar / `logits_gemm`), `a8c8066d` (`mlock`), and the `IQ8R` / `IQR-V4`-only pivot.
- **Adopted**: 8-bit indexer block max + 11-bit radix top-k, multi-token indexer candidate scoring, split Flash v2, double-buffered prefix-cache restore, adaptive `q=1` speculative drafting, and Markov pruning.
- **Rejected**: Weight conversion to `IQR-V4` / `IQ8R` (negative EV for `gfx1201` FP8 WMMA and 32 GiB VRAM capacity per card), and unconditional `mlock` (`AFF_POOL_MLOCK=0` default).
