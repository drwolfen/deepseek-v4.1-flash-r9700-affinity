### 2.1 Architecture Summary (`F1–F8`)

1. **`F1` — Sparse Indexer `idx_wq_b` FP8 Activation Quant (`AFF_IDX_WQB_FP8=1`, `baf61cd`)**:
   `DenseGpu::ps_for` preserves preshuffled FP8 weights on `idx_wq_b` (`(cols % 128) == 0`). Both `indexer_one` and `batch_indexer_q` quantize input activations via `batch_quant_tm_fp8_hip` (`D.i_q8`) and dispatch `batch_gemm_fp8_hip` (`D.b_y` / `D.i_q`) instead of BF16-fallback matmul.
2. **`F2` — Grouped Block-32 `attn_out_a` Direct FP8 Path (`AFF_ATTN_OUT_A_FP8=1`, `b1e65c4`, `baf61cd`)**:
   `batch_attn_out_prep_fp8_hip` reads `[nb][ng * group_dim]` F32 heads, converts to BF16 in LDS, applies the inverse RoPE tail, quantizes per-32 UE8M0 under `o_fp8_qdq_wave32` rules, and writes contiguous `[ng][nb][group_dim]` E4M3 + `[ng][nb][group_dim >> 5]` UE8M0 into `D.b_heads` / `D.a_q`. `batch_gemm_fp8_grouped_b32_hip` consumes those packed buffers across all `ng` groups in one launch (`ps` enabled on `attn_out_a`), replacing the `BF16` grouped `batch_gemm_grouped_hip` fallback.
3. **`F3` — DSpark `mtp_main_proj` FP8 Quantized Tap (`AFF_MTP_PROJ_FP8=1`, `b1e65c4`, `baf61cd`)**:
   Extends `batch_quant_tm_fp8_hip` with an optional `n_live` parameter that emits zeroed `0x00` E4M3 bytes and `1.0f` scales for padded rows `tok >= n_live`. `DenseGpu::draft_mtp_proj` preserves preshuffled FP8 on `mtp_main_proj` (`(cols % 128) == 0`) and feeds `batch_quant_tm_fp8_hip(..., n)` straight into `batch_gemm_fp8_hip(..., ps=true)`, bypassing `draft_transpose_pad_kernel`.
4. **`F4` — Packed Hardware E4M3 TP=2 All-Reduce (`6383b19`)**:
   Replaces per-element `__hip_fp8_e4m3` scalar conversions in `tp_ar_fp8_kernel` and `tp_ar_fp8_staged_kernel` (`src/gpu/tp_allreduce.hip`) with clamped 4-byte `pack4_e4m3` (`__builtin_amdgcn_cvt_pk_fp8_f32`) and packed `aff::e4m3_decode_pk<false/true>` while strictly preserving ascending rank accumulation order across peers.
5. **`F5` — Raw MXFP8 Engram H2D + On-GPU Requant (`AFF_ENGRAM_RAW_H2D=1`, `b1e65c4`, `baf61cd`)**:
   `EngramTables::gather_mxfp8` copies raw `[in_dim B E4M3 | (in_dim / 32) B E8M0]` rows (`raw_mxfp8_stride()`) directly into `eng_raw_` instead of CPU-dequantizing to F32 (`engram_mxfp8` hooks on `DenseOps` and `BatchOps`). On device, `engram_mxfp8_requant_fp8_hip` (`engram_mxfp8_requant_fp8_kernel`, **`11` VGPRs / `16` occupancy**) decodes E4M3+E8M0 in Wave32 DPP and emits per-128 E4M3 + F32 scales matching `gather + batch_quant_tm_fp8_hip` bit-for-bit.
6. **`F6` — Group-128 FP8 E4M3 Target LM Head (`AFF_LMHEAD_FP8=1`, `b1e65c4`, `baf61cd`, `54692df`)**:
   `DenseGpu::reg` chunk-quantizes (`kChunkRows = 1024`) target `output` weight shards on load via `quantize_bf16_to_fp8_g128_hip` into `[nrows][ncols]` E4M3 (`fp8_data`) + `[nrows][ncols/128]` BF16 scales (`fp8_scales`) — **`320.6 MiB/shard`** vs `483.6 MiB/shard` for `bf16x12` — and dispatches `matvec_fp8_g128_multix_hip` across decode and `batch_head*` (`T <= 8` chunks). Promoted to default ON in `54692df` (`lmhead_fp8_enabled()`, freeing VRAM for **`+27` resident MoE experts**); `supersedes AFF_LMHEAD_BF16X12` logs only when `AFF_LMHEAD_BF16X12` is explicitly set non-zero.
7. **`F7` — Hardware `e4m3_enc` & Subnormal Carry Fix (`6383b19`)**:
   Updates `aff::e4m3_enc` in `src/gpu/device_math.h` to use hardware `__builtin_amdgcn_cvt_pk_fp8_f32` (with clamped `e4m3_enc_sw` fallback) and fixes the `[7.5 * 2^-9, 8 * 2^-9)` subnormal-to-normal rounding carry (`0x08`) consistently across `device_math.h` (`e4m3_enc_sw`), `attention_gpu.hip` (`e4m3_encode`), and `attn_flash.hip` (`kv_encode_fp8r_row`).
8. **`F8` — 2-Wide Norm-Quant & Uniform `AFF_O_FP8_QDQ=1` (`b1e65c4`, `baf61cd`)**:
   Part A pairs consecutive elements via 2-wide `__builtin_amdgcn_cvt_pk_fp8_f32` inside `batch_rms_norm_q8_kernel`, `hcn_norm_kernel`, and `hcn_norm_v41_kernel`. Part B unifies `o_fp8_qdq_enabled()` (`AFF_O_FP8_QDQ=1` default ON) across both single-token `attn_out` and batched `batch_attn_out`.

## 3. NUMA Node 0 Pinning & `--cap-add SYS_NICE` Fix (`54692df`)

- **Root Cause**: Default Docker seccomp blocks `SYS_mbind` (`EPERM`), causing the runtime to skip `MPOL_PREFERRED -> node 0` when allocating the `182.4 GiB` `host_pool`.
- **Topology**: Both R9700 GPUs attach to NUMA Node 0 (`376.5 GiB` RAM; NUMA distance **`10`** local vs **`21`** remote on Node 1). Hard-restricting containers with `--cpuset-mems=0` risks Node 0 OOM because `182.4 GiB` (`host_pool`) + `188.8 GiB` (`Engram`) = `371.2 GiB`.
- **Fix (`54692df`)**: Adding `--cap-add SYS_NICE` in [`deploy/run.sh`](../deploy/run.sh) and [`deploy/deepseek-v41-affinity.service`](../deploy/deepseek-v41-affinity.service) unlocks `SYS_mbind(MPOL_PREFERRED -> node 0)` (`rc=0`), pinning **`47,804,160 / 47,804,160` (`100.0%`)** of `host_pool` pages on NUMA Node 0 while letting `Engram` mmap pages spill safely to Node 1 with **`0.00 pgscank/s`** during workloads.

## 7. Operational Note: Per-Boot Bimodal Variance & Benchmark Methodology

During multi-arm validation, a per-container-boot `~33 tok/s` (SLOW) vs `~45–48 tok/s` (FAST) bimodal regime was observed at the host/ROCm boundary across **both** `v5.4.0` and `v5.6.0-rc1`:

- **`v5.4.0`**: `phase5_v540_rc5` booted in FAST (`l4k tg2 = 48.24 tok/s`, warmup `req00 = 0.50 s`) while `phase5_v550/b2/arm1_v540` booted in SLOW (`l4k tg2 = 34.40 tok/s`, warmup `req00 = 0.64 s`).
- **`v5.6.0-rc1`**: `f6_server` booted in FAST (`l4k tg2 = 48.73 tok/s`) whereas hot sequential containers (`d2`/`d2_numa` `arm2`, launched at `GPU[1]` junction `61–62 C` climbing to `85–90 C`) booted into SLOW (`31.50–34.79 tok/s`).

To keep arm-to-arm comparisons cleanly within the FAST regime, the 3-boot `AFF_TRACE=dense,events` + 1 Hz sysfs diagnostic (`b1_v560_fp8 -> b2_v550 -> b3_v560_fp8`) and `d2_final` enforced:
1. Cooling `GPU[1]` junction temperature to **`<= 52 C`** before container launch.
2. Verifying initial warmup **`req00 <= 0.52 s`** alongside `mclk=1258 MHz`, `fclk=2400 MHz`, and `sclk=3205–3574 MHz` prior to recording benchmark runs.
