## 1. Hardware, Service & Safety Architecture

### 1.1 Target System & Link Topology
- **Host**: Intel Xeon Platinum 8160 (24 physical cores / 48 threads per socket, NUMA node 0 assigned to cores `0-23,48-71`).
- **Accelerator**: Dual AMD Radeon AI PRO R9700 2×32GB (RDNA 4 architecture, target `gfx1201`), ROCm 10.1.0-full.
- **Interconnect**: PCIe 3.0 x16 host-to-device uplink (~12.8 GB/s practical bandwidth per link). Expert shard streaming and KV transfer orchestrate across a unified 200 GiB host DRAM slab (`--host-pool-mib 200000`).
- **SELinux Compatibility**: Production Docker containers run strictly with `--security-opt label=disable` and `--ipc=host` to ensure unhindered device node access (`/dev/kfd`, `/dev/dri`) on host SELinux.

### 1.2 Dual Endpoint Topology
The live inference service operates two unified endpoints with 100% API and semantic parity:
1. **Port `:8000`**: Primary OpenAI-compatible Docker container (`deepseek-affinity:v5.1.0`).
2. **Port `:8080`**: High-availability reverse proxy (local port-8080 TCP proxy) forwarding to `:8000` for client pipelines.
Both endpoints expose identical health semantics (`GET /health`), model discovery (`GET /v1/models`), and chat streaming (`POST /v1/chat/completions`).

### 1.3 Hard Safety Invariants (Do-Not-Repeat Invariants)
All engine enhancements and configuration settings strictly enforce the production invariants:
- **Target LM Head BF16**: Never enable `AFF_LMHEAD_INT4=1` on the primary model (INT4 head incurs significant perplexity loss). Draft model head INT4 is maintained (`AFF_DRAFT_HEAD_INT4=1`).
- **Equal Micro-Batching**: `AFF_EQUAL_UBATCH=0` (kept disabled; benchmarking proved it adds kernel overhead without reducing chunk count).
- **Prefetch Ring**: `AFF_PREFETCH_RING=0` (kept disabled; ring prefetch consumes 8–12 resident expert slots without throughput gain on PCIe 3.0 x16).
- **GPU Resident MoE**: MoE expert computations run 100% on GPU tensor cores; zero MoE compute is offloaded to CPU.
- **No Live KV Unmapping**: Live `kv_shrink_to` page unmapping is forbidden to prevent page table fragmentation and deadlock during multi-turn streaming.
- **Model Storage Immutability**: All model files (`model-uc-1017.aff`, `model-moonmath-1017.aff`, `imatrix-dsv41-262144.gguf`, `.dspark.aff`, `.engram`, and base FP8 tables) remain immutable and read-only.

## 3. Upstream & Fork Cherry-Pick A/B Evaluations

A comprehensive systematic evaluation of proposed candidate optimizations and PRs was conducted prior to final release freeze:

### 3.1 #958: `AFF_DRAFT_SKIP_MASKED` DSpark Ring Attention Tile Skip (**ACCEPTED - Default 1**)
- **Mechanism**: In DSpark ring attention verification, tokens in a sequence cannot attend to subsequent masked positions. When an entire tile falls within the causal mask boundary, skipping compute and memory traffic entirely reduces tile latency.
- **A/B Result**:
  - `AFF_DRAFT_SKIP_MASKED=0`: Decode median `16.93 tok/s`, peak `20.98 tok/s`.
  - `AFF_DRAFT_SKIP_MASKED=1`: Decode median `20.69 tok/s` (**+22.2%**), peak `21.70 tok/s`.
- **Verdict**: Enabled as default in engine (`draft_skip_masked_enabled() -> true`).

### 3.2 #980 / #992: `AFF_ATTN_LOOKAHEAD` Decode Prefetch & Wave32 DPP (**REJECTED AS DEFAULT - Default 0**)
- **Mechanism**: Initiates asynchronous L2 prefetch of next-step KV cache rows during attention reduction, combined with Wave32 Data-Parallel Primitives (DPP) across lane registers.
- **A/B Result**:
  - `AFF_ATTN_LOOKAHEAD=1` alone: Decode median `18.29 tok/s`, peak `19.67 tok/s`.
  - Combined `AFF_DRAFT_SKIP_MASKED=1` + `AFF_ATTN_LOOKAHEAD=1`: Decode median dropped from `20.69 tok/s` to `18.33 tok/s` (**-11.4% regression**).
- **Root Cause**: On PCIe 3.0 x16 host uplink with RDNA 4 Wave32 scheduling, prefetch instructions contended for register pressure and memory issue slots with active GEMM math.
- **Verdict**: Reverted default from `1` to `0`. Retained as opt-in flag for future high-bandwidth architectures.

### 3.3 #989: State-Only Delta Prefix Cache Snapshots & `ignore_eos` (**ACCEPTED - Default 1**)
- **Mechanism**: Multi-turn prefix cache snapshots previously rewrote entire KV states. #989 introduces delta serialization (`AFF_PCACHE_DELTA=1`), saving only newly allocated pages since the previous turn checkpoint, and implements `ignore_eos=true` streaming support for raw generation.
- **A/B Result**:
  - Turn 1: 26 tokens (TTFT 1.22s).
  - Turn 2: 170 tokens with 154 cached tokens (TTFT 0.86s vs baseline 1.22s, **1.42× speedup**).
  - Raw completions correctly streamed exact requested token counts (64/64 tokens).
- **Verdict**: Enabled by default.

### 3.4 #1006: GPU `gridDim.y` Hardware Overflow Guard (**ACCEPTED**)
- **Mechanism**: On sequences exceeding 65,535 prefill tokens, launch configurations indexing `blockIdx.y` overflowed the hardware limit on ROCm. #1006 tiles the batch dimension across a 2D grid structure to safely scale prefill beyond 64K tokens.
- **Verdict**: Merged and verified in 128K context prefill.

### 3.5 #1020: DSML Nested XML Tag Arg Protection & Multi-Call Splitting (**ACCEPTED**)
- **Mechanism**: Fixed premature parser termination when tool call arguments contained literal `<tool_call>` or `<antml:invoke>` tags, and split concatenated multi-call tool blocks into distinct OpenAI function-call array items.
- **Verdict**: Merged and passed DSML nested XML test suites.

### 3.6 #983 / #984: Stream RAW Analysis & Multi-Row Dedup (**ACCEPTED**)
- **Mechanism**: Analyzed Read-After-Write (RAW) data hazard invariants across HIP streams and added multi-row unique-read deduplication unit testing.
- **Verdict**: Verified thread-safe execution across multi-stream expert transfers.

### 3.7 #995: Shared KV Attention Pruning (**NOT APPLICABLE**)
- **Analysis**: Upstream PR #995 optimizes dense Multi-Head Attention by pruning redundant multi-head key-value projections. DeepSeek-V4.1 utilizes Multi-Head Latent Attention (MLA) with decoupled low-rank KV compression ($d_c = 512$), making dense multi-head pruning structurally inapplicable.

## 4. Stage 1C Hadamard on Pre-Quantized MXFP4 Pilot Analysis

To explore whether block-32 Walsh-Hadamard transformation (`AFF_HADAMARD_ROT`) could reduce outlier activations on quantized MoE weights, a pilot study was executed on pre-quantized MXFP4 expert blocks:

- **Hypothesis**: Applying a randomized Hadamard orthogonal rotation matrix prior to linear projections will smooth activation outliers across channels.
- **Measurement**:
  - Baseline Cosine Similarity: `0.982901`
  - Post-Hadamard Cosine Similarity: `0.061502`
  - Signal-to-Quantization-Noise Ratio (SQNR): **`-17.343 dB`** (catastrophic signal loss)
- **Root Cause Analysis**: The Hadamard transformation is mathematically valid only when applied to continuous FP32/BF16 weights **during the quantization process before grid scales and codebook indices are established**. Applying rotation to already-quantized MXFP4 weights scrambles the non-linear quantization boundaries, multiplying error rather than dampening it.
- **Engineering Decision**: Runtime Hadamard rotation on pre-quantized weights was rejected and skipped. Block-32 Hadamard transforms remain strictly confined to offline quantizer workflows (`aff_quantize`).
